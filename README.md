# Ознакомительная часть

Программно-аппаратный комплекс для автономного и ручного управления сельскохозяйственным трактором.
Система перехватывает органы управления (газ через сервопривод, коробку передач и гидравлическое орудие по RS485, актуаторы педалей тормоза/сцепления через АЦП) и водит трактор по GPS-треку, полученному от серверов «Русагро».

Управление возможно с двух источников:

- **Локальная USB-клавиатура** (нумпад) в кабине.
- **Веб-интерфейс** на планшете/мониторе кабины — телеметрия, карта, логи, загрузка треков/границ и переключение режимов (органами управляем только в ручном режиме на мониторе).

Ключевые цели: отказоустойчивость, аппаратные и программные блокировки, предсказуемые стейт-машины.

---

## Архитектура (многопоточность)

Система построена на одном главном цикле и нескольких фоновых потоках-демонах.

- **Главный цикл (`main.py`)** — работает на частоте ~100 Гц (`time.sleep(0.01)`). Без блокирующих вызовов: вся «тяжёлая» работа вынесена в потоки.
- **Веб-сервер (Flask)** — фоновый поток, поднимает UI на `http://0.0.0.0:5000`.
- **GPS-поток (`core/gps_sensor.py`)** — читает и парсит NMEA (GGA/GNS/RMC/VTG) в фоне. Координаты принимаются при любом типе решения (GPS/DGPS/PPP/RTK/DR); критерий пригодности — свежесть данных (`GPS_STALE_SEC`), сырое качество остаётся в телеметрии.
- **Поток клавиатуры (`hardware/keyboard.py`)** — слушает нажатия нумпада через `evdev`.
- **Поток отправки RS485 (`hardware/rs485.py`)** — блокирующая отправка по шине вынесена в отдельную очередь, чтобы не тормозить главный цикл.

Связь между потоками строго потокобезопасная:

- команды (с веба и клавиатуры) идут в главный цикл через `queue.Queue` плоскими словарями `{"action": ...}`;
- телеметрия для веба читается из общего `tractor_status` под `status_lock`.

## С чего всё начинается

Точка входа — функция `main()` в [main.py](main.py). Последовательность запуска:

1. `install_stdout_tee()` — перехват `stdout` в кольцевой буфер логов (для панели логов на веб-странице).
2. `pigpio.pi()` — подключение к демону `pigpiod` (если не запущен — система останавливается).
3. `setup_gpio()` — инициализация пинов актуаторов в безопасное состояние (LOW).
4. Инициализация I2C/ADS1115 (если включён флаг `ENABLE_I2C` в [config.py](config.py)).
5. Создание менеджеров железа: `RS485Manager`, `ActuatorManager`, `KeyboardManager`, `GasManager`, `CanManager`.
6. Запуск `GPSSensor` (если `ENABLE_GPS`) и создание `TrackManager`.
7. Запуск веб-сервера `run_server(...)` в фоновом потоке и `webbrowser.open("http://127.0.0.1:5000/")`.
8. Вход в главный цикл `while True`.

Главный цикл на каждом такте обновляет `tractor_status` и проходит по блокам:

- **Блок 1 — Чтение очереди команд.** Разбирает `command_queue`: загрузка маршрута/границы, переключение режимов, экстренный стоп, ручные команды газа/коробки/орудия/актуаторов.
- **Блок 1.5 — Актуаторы.** В режимах KEYBOARD и BORDER прокручивает стейт-машину актуаторов педалей.
- **Блок 3 — Навигация (автопилот).** Ищет целевую точку (Pure Pursuit / Haversine), задаёт скорость круиз-контролю, поднимает/опускает орудие по таймеру (5 с поднять / 15 с опустить), завершает маршрут.
- **Блок 3.5 — Режим BORDER.** По геометрии границы поля решает, когда поднять/опустить орудие и сбросить/вернуть скорость (S0 у края, S1 в поле); круиз-контроль газа крутится каждый такт.

При выходе или аварии блок `finally` переводит железо в безопасное состояние: актуаторы обесточены, GPIO очищены, `pigpio` остановлен.

## Режимы управления

`CONTROL_MODE` принимает три значения:

- **KEYBOARD** — ручное управление с нумпада (режим по умолчанию).
- **AUTO** — автопилот по загруженному GPS-треку.
- **BORDER** — полуавтомат у границы поля: газ и орудие ведёт система, руль (физический), коробка и актуаторы остаются на водителе. Включается клавишей «+» (`toggle_border`) или с планшета (`start_border_mode`/`stop_border_mode`).

## Правило приоритета:

**клавиатура всегда главная, все переходы идут через KEYBOARD.** Любое выключение автопилота или BORDER (с планшета, с клавиатуры, конец маршрута, смена маршрута/границы) возвращает систему в KEYBOARD с газом в минимум; при выключении BORDER незавершённый импульс орудия останавливается командой СТОП. Включить AUTO из BORDER (и наоборот) нельзя — сначала выключите текущий режим.

# Настройка файлов config.txt и cmdline.txt

## config.txt

```bash
sudo nano /boot/firmware/config.txt
```

В конце файла:

```bash
[all]
dtoverlay=disable-bt
core_freq=250
# can sniffer config
dtparam=spi=off
dtoverlay=mcp2515-can0,oscillator=12000000,interrupt=25,spimaxfrequency=2000000
dtoverlay=spi-bcm2835-overlay
enable_uart=1
dtoverlay=uart3
dtoverlay=uart5
#dtoverlay=i2c-gpio,bus=3,i2c_gpio_sda=17,i2c_gpio_scl=27
dtoverlay=vc4-kms-v3d
#DSI1 Use
dtoverlay=vc4-kms-dsi-waveshare-panel-v2,10_1_inch_a
#DSI0 Use
#dtoverlay=vc4-kms-dsi-waveshare-panel-v2,10_1_inch_a,dsi0
```

## cmdline.txt

```bash
sudo nano /boot/firmware/cmdline.txt
```

Заменить на(**ОБЯЗАТЕЛЬНО В ОДНУ СТРОКУ**):

```bash
console=ttyAMA0 console=tty1 root=PARTUUID=90a9f106-02 rootfstype=ext4 fsck.repair=yes rootwait quiet splash plymouth.ignore-serial-consoles cfg80211.ieee80211_regdom=GB
```

# Настройка splash-screen с логотипом XFarm и автозапуск сборки

## Настройка splash-screen

В современных версиях ОС (Raspberry Pi OS Bullseye и Bookworm) за графику при загрузке отвечает системная утилита Plymouth.

1. **Подготовьте изображение** - Создайте картинку в формате .png с разрешением вашего монитора.
   Назовите файл splash.png и сохраните его на Raspberry Pi.
2. **Сделайте бэкап стандартной заставки** - Откройте терминал и скопируйте оригинальный файл.

   ```bash
    sudo cp /usr/share/plymouth/themes/pix/splash.png /usr/share/plymouth/themes/pix/splash.png.bak
   ```

3. **Скопируйте заставку в систему** - Перенесите изображение с заменой старого. Если картинка лежит в папке Downloads, команда будет такой

   ```bash
    sudo cp ~/Downloads/splash.png /usr/share/plymouth/themes/pix/splash.png
   ```

4. **Скройте текстовые логи** - Чтобы поверх картинки не бежали строчки системного кода, нужно отредактировать параметры загрузки.
   - Откройте файл конфигурации:

     ```bash
     sudo nano /boot/firmware/cmdline.txt
     ```

     (Примечание: если у вас старая версия Raspberry Pi OS, путь будет `/boot/cmdline.txt`)

     Найдите строку с параметрами и убедитесь, что в ней есть следующие слова (если этих параметров нет, добавьте их в конец строки, не создавая новых строк):

     `quiet splash logo.nologo vt.global_cursor_default=0`

     Сохраните файл, нажав Ctrl+O, Enter, Ctrl+X.

5. **Примените изменения** (_Займет около минуты_) - Введите следующую команду в терминале, чтобы пересобрать загрузочный образ с новой картинкой:

   ```bash
    sudo plymouth-set-default-theme -R pix
   ```

   после перезагрузите Raspberry Pi

   ```bash
    sudo reboot
   ```

## Автозапуск сборки

1. **Создайте скрипт автозапуска** - Создайте файл `startup.sh` в домашней директории Raspberry Pi (например, `/home/user/startup.sh`) и добавьте в него команды для запуска сборки:

   ```bash
   nano /home/user/startup.sh
   ```

   Вставьте в него следующий код.

   ```bash
   #!/bin/bash
   sleep 5
   chromium-browser --kiosk --noerrdialogs --disable-infobars --password-store=basic http://127.0.0.1:5000 &
   cd /home/user/Desktop/traktor-RusAgro-v0.3/
   echo "user" | sudo -S ./venv/bin/python main.py
   ```

   Сохраните файл, нажав Ctrl+O, Enter, Ctrl+X.

2. **Сделайте скрипт исполняемым** - В терминале выполните команду:

   ```bash
   chmod +x /home/user/startup.sh
   ```

3. **Добавьте скрипт в автозагрузку** (_Графический автозапуск_) - создайте ярлык, который система будет автоматически дергать при появлении рабочего стола.

   Сначала создайте папку для автозапуска

   ```bash
   mkdir -p /home/user/.config/autostart
   ```

   Создайте файл конфигурации:

   ```bash
   nano /home/user/.config/autostart/traktor.desktop
   ```

   Вставьте в него эти строки:

   ```bash
   [Desktop Entry]
   Type=Application
   Name=TraktorStartup
   Exec=/home/user/startup.sh
   Terminal=false
   ```

   Сохраните файл, нажав Ctrl+O, Enter, Ctrl+X.

   Перезагрузите Raspberry Pi `sudo reboot`
